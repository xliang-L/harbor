# 使用指南

## 完成第一轮营销工作

1. 在首页建立品牌，填写产品、受众与市场。
2. 进入「活动与商品 → 目标与规范」，填写目标、语气、价值主张、禁用表述及指标目标。
3. 导入商品或来源资料，检查原文和演示标记。商品导入不等于事实认证。
4. 在「运营流程 → 来源与事实」逐字引用证据，明确品牌通用或特定商品范围，填写确认人；必要时设置有效期与属性值。
5. 从市场动态生成行动假设，选择一条创建文案与分镜，人工核查全文及来源。
6. 批准具体内容版本，建立活动及渠道计划，确认账号标签、文案、UTM 和排期。
7. 完成渠道与活动审核，下载交付包，在外部平台人工发布。
8. 登记实际交付时间、链接或凭证、记录人。人工回执不等于平台独立核验。
9. 读取报表，填写明确统计窗口，预览并导入指标；根据观察值安排下一轮假设。

默认模板模式可走通上述本地流程。模型、公开采集与账户只读报表需要各自的配置和访问条件。

## 事实变化后怎么办

事实撤回、到期或出现潜在冲突后，相关内容和交付入口会要求核查。原审批、版本、指标和已发生的交付仍保留。

如果只是重新确认有效期，追加一条新的确认记录；旧内容不会自动恢复审批。进入内容工作台的明确事实复核流程，检查全文和分镜、选择新依据并说明原因，生成新版本后重新审核。

属性冲突只比较同一范围下登记的不同文字值，不自动判断事实真伪、自由文本语义或单位等价。

## 审批与回执

内容审批绑定具体修订及品牌规范。渠道审批还绑定账号、文案和计划时间；未来排期检查交付时点的事实资格。

人工回执绑定排期和版本，实际交付时间不能早于内容/渠道审批或落在事实生效之前。同渠道账号的重复凭证会被阻止。记录错误时填写操作者和原因撤销，再重新录入；撤销保留原始快照，不操作外部平台。

## 指标窗口

窗口采用 **含开始、不含结束** 的规则。一天报表应填写当天零点到次日零点；`date` 记录读取或导出报表的时间，不能早于窗口结束。

```json
{
  "contentId": "REPLACE_CONTENT_ID",
  "revisionId": "REPLACE_APPROVED_REVISION_ID",
  "url": "https://example.com/demo-post",
  "windowStart": "2026-01-01T00:00:00+08:00",
  "windowEnd": "2026-01-02T00:00:00+08:00",
  "date": "2026-01-02T09:00:00+08:00",
  "impressions": 100,
  "clicks": 5,
  "conversions": 0,
  "spend": 10,
  "currency": "CNY",
  "timezone": "Asia/Shanghai",
  "notes": "Synthetic example only"
}
```

相邻窗口可以累计。同一口径、同窗同值跳过；同窗数值变化、包含或部分交叠均提示冲突。只换读取时间、时区标签或币种不能把同一流量变成另一份数据。

旧无窗口记录保留但不计汇总，系统不从备注猜测日期。错误记录可填写原因撤销后重录；原值和历史保留。待核查或无可汇总数据不等于零效果。

## 文件格式

| 内容           | 格式                                                                            | 样例                                          |
| -------------- | ------------------------------------------------------------------------------- | --------------------------------------------- |
| 证据           | CSV / JSON，`title,url,publishedAt,text,demo`                                   | [证据模板](../fixtures/evidence-template.csv) |
| 商品           | CSV / JSON，`sku,title,description,price,currency,url`                          | [商品示例](../fixtures/products-demo.csv)     |
| Shopify 商品   | 导出 CSV 的 Handle、Title、Body (HTML)、Variant SKU、Variant Price              | [Shopify 示例](../fixtures/shopify-demo.csv)  |
| 指标           | CSV / JSON，明确起止窗口、读取时间、数值、币种与时区；可选 `campaignId/channel` | [指标模板](../fixtures/metrics-template.csv)  |
| HubSpot 联系人 | JSON，预览时映射字段                                                            | [联系人示例](../fixtures/hubspot-demo.json)   |
| 销售与退款     | 标准 CSV，先映射和预览，检查销售及退款关联                                      | [订单示例](../fixtures/orders-demo.csv)       |

证据、商品和指标每批最多 100 行 / 300 KB。指标必须关联曾批准的具体内容版本；样例中的 ID 不能直接代替你的实际记录。任一错误行会阻止整批导入。

同 SKU 商品导入跳过既有条目，不覆盖产品；商品更新与历史跟踪在后续路线中。Shopify 仅为文件导入，不连接商店、客户或订单账号。

## 数据备份

工作区数据在 `data/`，视频与导出在 `artifacts/`。使用 SQLite backup API 在线备份，或先停止服务再复制整个数据与产物目录。请不要只复制运行中的主数据库而忽略 WAL。

模型、GA4 与 Postiz 的配置见 [平台矩阵](PLATFORMS.md)。
